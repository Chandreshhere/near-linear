## Engine fixes closed by hand (wave 2)
- **Self-healing IndexedDB schema** (`openSchemaDb` in persistence.ts, shared with LocalTransport): store existence no longer depends on SCHEMA_VERSION discipline — missing stores trigger a +1 reopen that creates them. Kills the "object store not found" boot failure class.
- **DataCloneError on creates**: `toPlain` now deep-converts via mobx `toJS` (preserving undefined-valued snapshot keys) so MobX array proxies never reach structured clone. Verified: create → instant apply → queue drains → survives reload.
- **Boxless-trigger anchoring bug**: `display: contents` trigger wrappers gave the popper a 0×0 rect at (0,0) (the reported "menus open top-left"). Fixed in Menu/Popover (sidebar agent) and PickerMenu (by hand); ContextMenu keeps the boxless wrapper deliberately (pointer-anchored).

## Open bug found in Phase 9 (owner: data layer, NOT the agent surface)
- **`LocalTransport` cannot persist any CREATE — `DataCloneError`.** Repro with zero agent code: on any workspace page run
  `client.mutate.createIssue({…full row…})` — the row appears in the MobX pool, but `queue.pendingCount` stays 1 forever, `lastSyncId` never advances and the sidebar shows "Syncing 1". Instrumenting IndexedDB shows
  `IDBObjectStore.put` throwing `DataCloneError: … could not be cloned` inside `LocalTransport.#applyTransaction` (create branch).
  Cause: `TransactionQueue` is `makeAutoObservable`, so `this.queue.push(t)` deep-converts the transaction — `t.payload.labelIds` / `subscriberIds` become **MobX array proxies**. `toPlain()` only shallow-copies, so the proxies survive into `store.put(row)`; structured clone rejects a Proxy. Updates with scalar-only payloads (`{priority: 3}`) are unaffected, which is why it was not caught earlier — and `HttpTransport` never saw it because `JSON.stringify` flattens proxies.
  Fix belongs in `src/lib/data/*`: deep-plain the payload (`toJS(...)` in `toPlain`, or `JSON.parse(JSON.stringify(row))` before `store.put`). This also breaks the §14 create-issue modal, not just agent writes.

## Production-safety fixes (by hand, post-audit)
- `/api/sync/*` and `/api/integrations/inbound` are now **gated behind `NODE_ENV !== "production"`** (override: `ALLOW_SYNC_MOCK=1`). They previously compiled into a production build and would have served anyone, unauthenticated.
- The mutation mock returned **400 on a malformed batch**, which `HttpTransport` turns into a throw and the queue retries forever. It now returns `200` + a per-transaction `rejected` map, matching the contract a real backend must follow.

## Fixes worth remembering
- **macOS Option-key shortcuts never fired:** macOS rewrites `event.key` for Option combos (⌥V arrives as `√`, ⌥F as `ƒ`), so every `alt+*` binding in the registry silently failed. `src/lib/keyboard.tsx` now falls back to `event.code` when a spec sets `alt` — fixes ⌥V (save view) and ⌥U (inbox mark-all-read).
- **SyncClient cross-copy crash (Phase 6):** `SyncClient.get()` read `client.#disposed` on an instance pulled from the `globalThis` registry. Once the nav components made Turbopack emit a second module copy (SSR chunk + client chunk), the registry returned an instance of a *different* class copy and the ES `#private` read threw `Cannot read private member #disposed…`, 500-ing every workspace route. Fix: `disposed` is now a TS `private` (plain property, readable across copies) and `get()` never caches on the server — SSR builds a throwaway instance, so clients can't leak across requests on the Node global.
- Headless capture: plain `--virtual-time-budget` stalls on the app's open SSE stream; use puppeteer-core with a real wait (`scripts/probe.mjs`, `scripts/shoot-phase*.mjs`).
